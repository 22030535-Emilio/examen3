Examen 3 - Portal Académico SII ITC

Proyecto desarrollado para consumir la API REST del sistema SII ITC, permitiendo la autenticación de usuarios y visualización estructurada de su información académica.

🚀 Tecnologías Utilizadas

  • Framework Principal: Next.js (App Router) - Elegido por su robustez, manejo de rutas API integradas (crucial para solucionar el proxy CORS) y renderizado optimizado.
  • Librería UI: React 18
  • Lenguaje: TypeScript - Proporciona tipado estático para manejar las respuestas de la API de forma segura y predecible.
  • Estilos: Vanilla CSS (CSS Modules & CSS Variables) - Implementando un diseño único basado en "Neo-Brutalismo Moderno" con una paleta de colores verdes (Emerald/Forest).
  • Iconografía: Lucide React
  • Gestión de Estado: React Context API (para la autenticación global de la sesión).

📂 Arquitectura y Explicación de Archivos

A continuación se detalla la función de cada archivo clave dentro del código fuente (src/):

1. Configuración y Utilidades Base

src/lib/api.ts

Contiene la función apiFetch. Es el núcleo de las peticiones HTTP del frontend. Automáticamente inyecta el token JWT (usando Bearer y x-auth-token) en los headers y redirige las peticiones hacia nuestro Proxy local (/api/external/...) para evitar bloqueos CORS en el navegador.

src/context/AuthContext.tsx

Maneja el estado global de autenticación. Almacena el token JWT en el navegador (cookies/localStorage), provee las funciones login y logout a toda la aplicación, y protege las rutas redirigiendo al usuario si no está autenticado.

src/app/globals.css

Archivo de estilos globales. Define las variables de color (tema verde neo-brutalista), estilos de tipografía, animaciones básicas (skeleton de carga) y estilos base para las tarjetas (cards) de la interfaz.

2. Infraestructura Backend (Proxy)

src/app/api/external/[...path]/route.ts

Archivo crítico para el funcionamiento. Es un servidor intermediario (Proxy) construido con Next.js API Routes. Recibe las peticiones del frontend y las reenvía a https://sii.celaya.tecnm.mx.

  • ¿Por qué es necesario? Los navegadores bloquean peticiones directas desde localhost a dominios externos por políticas de seguridad CORS. Este archivo actúa como puente desde el lado del servidor de Node.js, donde CORS no aplica.
  • Funcionalidad: Desactiva validaciones SSL estrictas (común en certificados autofirmados de servidores universitarios), espera que se resuelvan los parámetros dinámicos (Next.js v15+ Promise params) y reenvía cabeceras de autorización y el cuerpo de la petición original.

3. Componentes Reutilizables

src/components/DataRenderer.tsx

Componente altamente dinámico que recibe cualquier estructura JSON (objeto o array) y lo renderiza visualmente sin importar su forma. Detecta automáticamente si un valor es una imagen (basado en el nombre del campo o el contenido web) para mostrar etiquetas <img>, trunca textos muy largos (como tokens), genera tablas para listados y tarjetas detalladas para objetos singulares.

src/components/PageWithRawData.tsx

Componente envoltura (wrapper). Muestra en la parte superior el diseño estilizado (usando DataRenderer) y en la parte inferior provee un botón colapsable que permite ver el JSON puro (Datos crudos) que devolvió la API. Esto es útil para depuración y para cumplir con requisitos de transparencia de datos.

src/components/Sidebar.tsx

El menú de navegación lateral responsivo que permite al usuario navegar de forma fluida entre Perfil, Calificaciones, Kardex, Horario y el módulo extra de Success Kit.

4. Vistas de la Aplicación (Rutas)

src/app/login/page.tsx

Pantalla de inicio de sesión. Envía las credenciales introducidas al proxy, intercepta la respuesta, extrae el token JWT específicamente de la ruta anidada data.message.login.token (formato específico de la API del SII ITC) y lo envía al contexto global de autenticación.

src/app/dashboard/page.tsx

Pantalla principal tras el login. Consume el endpoint de perfil (/api/movil/estudiante). Extrae los datos anidados en el campo message y los delega a los componentes de renderizado visual.

src/app/grades/page.tsx

Vista de Calificaciones. Consume el endpoint respectivo e incluye lógica compleja de procesamiento de datos para:

  • Buscar materias en tiempo real.
  • Filtrar asignaturas por su periodo correspondiente.
  • Asignar colores de estatus (Verde Excelente, Azul Bien, Amarillo Suficiente, Rojo Reprobado) dependiendo de la calificación numérica, que el código extrae automáticamente detectando patrones de nombres de campos numéricos (como 'calificacion', 'grade', etc.).
src/app/kardex/page.tsx

Historial académico. Procesa el arreglo devuelto por la API, agrupa iterativamente las materias por semestre/ciclo y las renderiza en un diseño de tablas separadas cronológicamente.

src/app/schedule/page.tsx

Horario semestral. Mapea la respuesta, agrupa las clases por día de la semana, las ordena secuencialmente por hora de inicio, filtra datos inconsistentes ("Sin día") y asigna un color único y estructurado a cada día de la semana en un formato de agenda horizontal.

src/app/success-kit/page.tsx

Funcionalidad Adicional (Propuesta del Equipo). Implementa un conjunto de herramientas extra para aportar valor real al estudiante. Incluye una "Calculadora de Promedio Objetivo (GPA)" interactiva y un tablón de noticias/recordatorios simulado por su propio backend de datos independiente.

🛠️ Instrucciones de Instalación y Ejecución

  1. Asegúrate de tener Node.js (v18 o superior) instalado en tu equipo.
  2. Clona o descarga este repositorio y extráelo.
  3. Abre una terminal apuntando a la carpeta raíz del proyecto.
  4. Instala las dependencias ejecutando: 
    npm install
  5. Inicia el servidor local en modo desarrollo: 
    npm run dev
  6. Abre tu navegador y dirígete a http://localhost:3000 (o el puerto que indique la terminal, comúnmente 3001).
